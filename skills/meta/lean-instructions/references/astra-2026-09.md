# OpenAI, "Rethinking skills and prompts for GPT-6 Astra" (2026-09-11)

Model-agnostic summary. Applies equally to Claude Fable 5.1 / Opus 5.

## Thesis
What used to need handholding and scaffolding no longer does. Extra instructions crowd
out code and facts, trigger compaction earlier, and make the model pause or misfire.

## 1. Better skills
- Descriptions as short as possible, saying when to use the skill.
  - Bad: "Create and validate Postgres schema migrations. Use when working with databases,
    queries, models, or persistence."
  - Good: "Create and validate Postgres schema migrations. Use when adding or changing a
    migration, or reviewing its rollout."
- Progressive disclosure: root document is a minimal router to supporting files.
- Drop elaborate step-by-step recipes; newer models handle nuance.
- Too many skills → context compaction and reading irrelevant guidance.

## 2. Up-to-date AGENTS.md
- Re-read the always-on file regularly; ask of each line whether it is still necessary.
  - Bad: "Before every edit, read architecture.md, database.md, and deployment.md."
  - Good: "Use architecture.md for service boundaries, database.md for schema changes,
    and deployment.md when preparing a deployment."
- Remove instructions that push full documentation review before routine edits.

## 3. Decision boundaries
- Language written to stop a less-aligned model from going too far now makes a
  well-aligned model too tentative.
- Replace with concrete permission statements, e.g.: "The local tests use disposable
  fixtures and have no production access. Run them, fix failures caused by the requested
  change, and rerun affected tests without asking for approval at each step."

## 4. Persistence
- The model tends to reach a first implementation and come back for review.
- Define done before starting; say explicitly if it should continue past the first
  working version, or where to stop if you want to review midway.

## Meta
Ask the model itself to audit existing skills, AGENTS.md, and prompts against these points.
